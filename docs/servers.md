# Servers as a work target

For a site that lives on a server you reach over SSH, SFTP, FTP or FTPS. The agent works on a local copy; nothing goes to the server until you click Upload.

- **Start with your files.** Open an existing folder with `.vscode/sftp.json`, then open its Server view. Choose files and click Review upload. Tau reads only the selected files on the server; no initial download or Git setup is needed. The connection approval is saved for this project on this machine and follows relevant connection settings, rather than a running session. Starting a thread does not contact the server. SSH host keys, certificates and credential access still get their usual checks.
- **Folders.** Before the first upload Tau lists the configured server folder once. If its names look unlike the local folder, choose another folder or confirm that the difference is intentional. Folders… reads one directory per navigation. Find a matching folder searches only after a separate click, at most two levels and 64 directories. Overrides stay in Tau's data; sftp.json is unchanged.
- **Branches.** Upload uses the current checkout, including local edits. Its preview identifies the branch and commit and refuses confirmation if the source changed. The saved server state is shared across branches and worktrees. Uploading a feature and returning to main shows the changes back to main and the known feature files to delete. Deletions require explicit selection. Other server files stay untouched.
- **Server files.** Click a file to read its current server version and compare it with your local file. Use server version replaces the local file after confirmation and keeps a local backup in History. Undo restores it only while the file has not changed again. Older explicit drift imports remain available, but they never block a new thread.
- **Upload.** The server view lists local candidates and changes against the last known server state. Unread files are labelled Not compared; size and timestamp do not establish equality. Nothing is preselected. Upload shows first what would go up, reads each file on the server again, and never overwrites a change made there unless you say so. Local deletions are listed as their own group. The agent can only propose an upload, as a card with a button.
- **Roll back.** Every upload is a deployment in the History tab, with the server's files as they were before. Roll back puts them back and is itself a deployment. Once your Git commit holds what went up, the deployment is marked committed.
- **The agent.** It reads the server freely (`server_read`, `server_list`, `server_diff`). Commands on the server (`server_exec`, SSH only) ask first unless you set the server to Full access in Settings → Servers. Recognizable Git write commands on the server are refused at every access level. This shell-text check can be bypassed and does not make server Git read-only. In a server project the agent's own commands reach only this machine and the package registries, until you allow more there.
- **On the phone.** The Servers sheet shows the status, and on a device with Full access it uploads and rolls back with the same preview first.

## Known limits

The network limit holds for Pi, the Agent SDK runtime and Codex (without any network for Codex); OpenCode, Antigravity, Cursor and Grok refuse to run there, and Windows has no limit at all ([Writing a package](EXTENSIONS.md#what-a-projects-commands-may-reach-servicesexecutionpolicy-new-in-api-1140)). Tau's own tools and your terminal are not limited. Spotting Git writes and local `ssh` to a server is a heuristic, not a wall. Many FTP servers list times to the minute, so a change of the same size within that minute is only found by a thorough check. See [ADR 0028](adr/0028-servers-as-a-work-target.md).

To create a new local project from a server, Add project → From a server… remains available. It explicitly downloads into a new folder. See [ADR 0043](adr/0043-server-uploads-from-existing-local-projects.md) for the existing-folder flow.
