# Project start options, 3 October 2026

Tau now offers **No project** in the new-thread picker, including when no projects have been added. Each selection allocates a fresh UUID folder under the owning host's Workspace Kit state. A continued thread keeps that folder. Saved drafts retain its opaque workspace identity, and the host re-admits its private allocations on restart. Changing the project on an existing draft carries its prompt and attachments through the existing draft controller.

Private thread workspaces are omitted from recent projects and the project catalog. They retain Files, Terminal and editor access. They expose no Git toolbar, worktree mode or turn checkpoints, even if the agent later initializes Git inside one. Deleting a thread does not delete its working files. Moving a started projectless thread into a project is outside this change.

Scratch creation refuses storage inside a Git repository, so a shell cannot accidentally discover that repository through its parent folders. The isolated development fixture supplies `GIT_CEILING_DIRECTORIES` at its own `.tau-dev` directory. Production does not add or change that variable. Paths are canonicalized before allocation and recognition, including symlinked storage and macOS `/var` paths.

When Run on chooses another machine, the local host verifies that the draft belongs to a private scratch workspace, asks the chosen machine's Workspace Kit to allocate its own folder and starts the thread there with that machine's opaque workspace ID. Existing project matching and repository transfer remain the paths for ordinary projects. The home host emits optional `UiSession.projectless` metadata from its cached projectless fact. The machine backend maps this explicit private-workspace classification to optional `HostBackendThreadRecord.project.listed: false`, so private remote threads remain visible without fabricating project rows locally. A missing project entry on an older host keeps the legacy listing behavior. The optional project-source `createThreadWorkspace` callback lets the picker allocate a private workspace through its kit rather than naming kit commands in core.

**New project** appears first among Add project sources and in its palette menu. A name creates a fresh folder in the configured project parent or a parent chosen through the host's native picker. Portable name validation rejects separators, control characters and reserved names; atomic nonrecursive creation rejects collisions without touching existing work. The folder receives a README, a stable color and two-letter SVG icon referenced by `t3.json`, and a Git repository with a first commit. Git setup failure keeps the files and reports a warning instead of inventing a commit identity.

This follows the feature scope of [T3 Code #13612](https://github.com/pingdotgg/t3code/pull/13612) and [#14527](https://github.com/pingdotgg/t3code/pull/14527). Tau uses its existing host-owned workspace identity, kit project facts, project sources and machine thread-start seams. It asks for the parent and rejects duplicate names instead of using an implicit managed parent and numeric suffixes.
