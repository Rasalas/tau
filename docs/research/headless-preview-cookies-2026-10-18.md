# Headless Preview cookie import, 18 October 2026

Primary-source research for `feat/headless-browser-cookie-import`, Tau base `1ab39107b2e4d3b12459ff063c85f555321d2038`. No browser process, profile, credential store or actual cookie import was opened. Product and tests were not changed. Chromium implementation links below are pinned to `cc610ab5f797526e71a0a787823e019cc15dea89`, the M153 source used by the related recording research; the protocol definitions were also checked at current upstream.

## Proposed approach

Reuse the existing selected-source/selected-site reader and its `CookieJar` interface. Map each cookie to root-session `Storage.setCookies({cookies: [cookie]})` in one owned Preview browser profile, without a page script, document navigation or public debugging port. Verify writes with `Storage.getCookies` before counting them as imported. Serialize shutdown, import and reopen with the existing Preview lifecycle queue so two browser processes never open the same target profile concurrently. Only Preview partitions and the existing private profile paths should be eligible. These are implementation recommendations.

A temporary browser followed by `Browser.close` is suitable for persistent cookies, but **session cookies require an explicit restore policy**. Closing the importer and reopening with Chrome defaults can lose the imported session immediately. The source supports adding `--restore-last-session` alongside the existing `--no-startup-window` for owned Preview browsers, with synthetic restart tests to confirm the intended behavior. Do not add an expiry to session cookies merely to make them survive restart.

## Mapping the existing cookie shape

The [official CookieParam definition](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Network.pdl) and [Chromium conversion](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/protocol/network_handler.cc#426) support this mapping:

| Tau `CookieToWrite` | CDP `Network.CookieParam` | Detail |
| --- | --- | --- |
| `name`, `value` | unchanged | Pass only over the owned private pipe; never return or log values. |
| `url` | unchanged | HTTP(S) setting URL. It supplies the host when no domain is present. An HTTPS URL makes the resulting cookie secure in this Chromium conversion. Tau already builds URL scheme consistently with `secure`. |
| optional `domain` | preserve only when present | Tau supplies a leading-dot domain only for domain cookies. Preserve that dot. Omit the field for host-only cookies; do not widen host-only cookies to a parent domain. |
| `path` | unchanged | Send explicitly instead of relying on URL-derived defaults. |
| `secure`, `httpOnly` | unchanged | Browser-level cookie operations support HttpOnly; no `document.cookie` access is required. |
| optional `expirationDate` | `expires` | Seconds since Unix epoch, not milliseconds. Omit for a session cookie. Zero is an expired timestamp, not a session marker. |
| `sameSite: "unspecified"` | omit `sameSite` | Preserve an undeclared attribute. This is distinct from explicit `None`. |
| `sameSite: "no_restriction"` | `sameSite: "None"` | Explicit unrestricted SameSite setting. Chromium still enforces applicable Secure/acceptance rules. |
| `sameSite: "lax"` / `"strict"` | `"Lax"` / `"Strict"` | CDP enum casing differs from Electron. |

Do not invent a partition key. An omitted `partitionKey` creates an unpartitioned cookie; the existing reader already skips partitioned source cookies. Do not confuse the Tau Preview profile partition name with a CHIPS top-level-site partition key. [CookieParam definition](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/third_party/blink/public/devtools_protocol/domains/Network.pdl#785), [existing reader](../../kits/preview/cookie-read.ts).

The conversion clears a domain without a leading dot and builds a host cookie from its host. A leading-dot domain normally produces a domain cookie. Chromium's [domain canonicalizer](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/net/cookies/cookie_util.cc#379) treats an exact IP-address domain, even with a leading dot, as host-only. Intranet/public-suffix cases can also canonicalize to a host cookie or be refused. Compare canonical stored domains during readback, not a blindly dot-prefixed input. An IPv6 URL needs URL brackets; its stored canonical domain follows Chromium's URL host representation.

Expiry may be normalized rather than reproduced exactly. [CanonicalCookie::ValidateAndAdjustExpiryDate](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/net/cookies/canonical_cookie.cc#265) caps a long lifetime at 400 days, or a shorter limit for feature-enabled insecure cookies. Confirm persistent versus session state and a sensible future expiry; a byte-for-byte expiry comparison would reject accepted cookies whose lifetime Chromium intentionally shortened.

## Root operation and acceptance

`Storage.setCookies` accepts optional `browserContextId`; it is not required. The [browser target registers StorageHandler](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/browser_devtools_agent_host.cc#248). [FindStoragePartition](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/protocol/storage_handler.cc#937) resolves an omitted ID through the default browser context and its default storage partition. No page attachment or `Network.enable` is needed. Do not create an incognito CDP browser context for import: that is a different cookie store, not the owned persistent profile.

The default profile must be loaded. [GetDefaultBrowserContext](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/devtools/devtools_browser_context_manager.cc#79) deliberately returns only an already loaded last-used profile. Startup with `--no-startup-window` is designed to load a profile without opening its window, but an early root request can still require a readiness check. [Profile loading decision](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/ui/startup/startup_browser_creator.cc#270).

`Storage.setCookies` has an empty success response, not an imported count. Its [handler](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/protocol/storage_handler.cc#465) reports invalid-cookie-fields errors for conversion/access failures. However, the [shared bulk setter](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/protocol/network_handler.cc#2516) discards each `SetCanonicalCookie` callback's `CookieAccessResult` and reports success after all callbacks. Therefore a successful call alone does not establish that its cookie entered the store. Sending one cookie at a time preserves Tau's existing per-cookie skip behavior, but does not remove the need for readback.

`Storage.getCookies` reads all cookies in the selected/default store. The [returned-cookie builder](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/content/browser/devtools/protocol/network_handler.cc#176) omits `sameSite` for `UNSPECIFIED`, returns `None` for `NO_RESTRICTION`, uses `session: true` plus `expires: -1` for session cookies, and preserves the canonical domain and path. A useful acceptance check matches canonical domain, path, name, value, secure, HttpOnly, unpartitioned state, SameSite and session/persistent status. Treat absence of returned SameSite as unspecified, not None. Keep readback values inside the host and discard them after comparison. This is an implementation recommendation based on the source, not a requirement of CDP.

## Flush, close and persistence limits

There is **no public CDP flush-cookie-store command** in the current [browser protocol command catalog](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json). Chromium has a private [CookieManager::FlushCookieStore](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/services/network/cookie_manager.cc#339) Mojo method, but it is not exposed through the CDP Storage/Network domains. A `Storage.getCookies` response only verifies in-memory visibility; it is not a disk flush.

Persistent cookie mutations normally batch to disk every 30 seconds, 512 operations, or an internal flush. The backing store's close path commits pending operations. [Cookie store batching](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/net/extras/sqlite/sqlite_persistent_cookie_store.cc#338), [backend close](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/net/extras/sqlite/sqlite_persistent_store_backend_base.cc#234).

`Browser.close` is documented as graceful shutdown. Its [Chrome handler](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/devtools/protocol/browser_handler.cc#132) merely schedules [CloseBrowserSoon](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/devtools/chrome_devtools_manager_delegate.cc#579) and immediately returns success. Await owned-process exit before reopening its profile. A timeout followed by SIGTERM/SIGKILL is cleanup, not proof of completed persistence. The current comment in [browser-process.ts](../../kits/preview/browser-process.ts) that Browser.close flushes the profile should not be interpreted as a crash-durability acknowledgement. Likewise, an adapter named `flushStore` must not claim to provide Electron's exact flush guarantee merely by issuing Browser.close.

## Session cookies and suppressing saved tabs

Chrome normally persists session cookies to its database, but it decides separately whether to restore them next startup. [ProfileImpl](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/profiles/profile_impl.cc#1270) returns `true` for persistence and restores old session cookies only after a recorded crash or when the startup policy restores the last session. Those flags flow through [ProfileNetworkContextService](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/net/profile_network_context_service.cc#1449). When restoration is false, the [cookie store deletes old session cookies during startup](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/net/extras/sqlite/sqlite_persistent_cookie_store.cc#845). A cleanly closed temporary importer followed by a default startup can therefore invalidate its own session-cookie import.

The sources support a way to retain session-cookie restore while suppressing automatic saved-page launch:

- [`GetSessionStartupPref`](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/ui/startup/startup_browser_creator.cc#896) sees `--restore-last-session` and selects LAST for an existing profile. New profiles intentionally ignore it because there is nothing to restore yet. A subsequent startup of that now-existing profile can use it.
- [`ProcessCmdLineImpl`](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/ui/startup/startup_browser_creator.cc#1135) sets silent launch for `--no-startup-window` and returns before browser/tab launch. The separate [`LaunchBrowser` path](https://chromium.googlesource.com/chromium/src/+/cc610ab5f797526e71a0a787823e019cc15dea89/chrome/browser/ui/startup/startup_browser_creator.cc#714) also guards actual `StartupBrowserCreatorImpl::Launch` behind `!IsSilentLaunchEnabled`; that helper returns true for `--no-startup-window`.
- The same switch/policy separation is present in official Chromium [112.0.5615.0 startup code](https://chromium.googlesource.com/chromium/src/+/refs/tags/112.0.5615.0/chrome/browser/ui/startup/startup_browser_creator.cc#1077) and its [session-cookie policy](https://chromium.googlesource.com/chromium/src/+/refs/tags/112.0.5615.0/chrome/browser/profiles/profile_impl.cc#1220). This establishes compatibility evidence at M112 and M153; it is not a claim about the switches' exact introduction version or every vendor build.

The conclusion that both switches permit cookie restore without saved-tab restoration is source-derived and needs an owned-profile restart test. It does not mean all Chromium background network activity is impossible. Keep the existing no-background-networking/no-extensions flags and confinement in place; a test should inspect targets and network activity before Tau intentionally creates/navigates its page. Use only Tau-owned profiles, never another browser's profile directory. No readback, graceful exit or restart test proves survival of power loss or forced termination.
