# T3 Code and Tau control sizes

Research on 7 October 2026 against T3 Code main at [`611132c171f3a821bd2e32f22261135cef6330ac`](https://github.com/pingdotgg/t3code/commit/611132c171f3a821bd2e32f22261135cef6330ac), committed at 11:33:44 UTC. Tau baseline is `ee487816516bdcc8f910c11ded1644f8cab2e423` plus the current sidebar-footer change to 36 px targets and 18 px icons. The official GitHub repository was opened during research and its source was cloned into `/tmp/t3-control-sizes-20261007`.

T3 Code already has a size system. Its common desktop button is 32 px high with 14 px text and 16 px icons. Compact controls use 28 or 24 px targets. A blanket 36 px target and 18 px icon would be a larger Tau design choice, not T3 parity. Tau's clearest mismatch is control text: sidebar search is 12 px, composer controls are 13 px, and Settings controls are often fixed at 12.5 px.

## Measurement assumptions

T3 sizes below are inferred from source classes, not measured in a running T3 window. The desktop column assumes the `sm` breakpoint applies, default interface size 16 px, default browser zoom, and Tailwind's default spacing unit of 0.25 rem. Thus `h-8` is 32 px, `size-4` is 16 px, `text-sm` is 14 px, and `text-xs` is 12 px. T3 imports Tailwind directly without overriding its spacing unit. Settings sets the root font size, so changing interface size scales rem-based text, icons, and targets together. The source defaults are interface 16 px, prompt 14 px, and code 13 px. [Tailwind import](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/index.css#L1), [font defaults](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/packages/contracts/src/settings.ts#L129), [root application](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/appearanceFonts.ts#L118).

Tau values use default desktop density 1, text scale 1, and Text size Normal. Runtime values supplied by the parallel Tau inspection use `getComputedStyle` and element bounds in an isolated desktop instance. Source confirms the desktop type tokens: meta 12, controls 13, body/input 14, leading rows 15, thread heading 17, page heading 24 px. [Tau tokens](../../src/renderer/tokens.css#L194), [ADR 0029](../adr/0029-type-scale-per-device-class.md).

Font size alone does not establish optical parity. T3 uses the OS sans stack, which starts with `-apple-system` on macOS. Tau uses Figtree first. Their glyph widths, cap heights, and weight appearance differ. T3's mono stack also prefers SF Mono; Tau uses `ui-monospace` then SFMono-Regular. [T3 font stacks](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/appearanceFonts.ts#L20), [Tau font stacks](../../src/renderer/tokens.css#L185).

## Existing rules and useful exceptions

T3's shared Button gives named sizes with explicit height, icon, and text classes. Desktop defaults are 32/16/14; `sm` 28/16/14; `xs` 24/14/12; `compact` 28/14/12; `icon-micro` 20/12 and `icon-tiny` 16/12. `icon-lg` is a 36 px target with a 16 px icon, while `icon-xl` is a 40 px target with an 18 px icon. Target and icon sizes are independent. Explicit SVG `size-*` classes bypass the default icon rule. [Button variants](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/components/ui/button.tsx#L19).

T3 also treats chevrons, tiny clears, provider marks, and stop glyphs as exceptions. These are deliberate roles, not evidence that every small icon should grow. Coarse-pointer controls add invisible hit-area expansion; sidebar header controls use a 48 px area, and common Buttons use a minimum 44 px after-element. Visual box and pointer target must be recorded separately. [Sidebar expansion](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/components/sidebar/SidebarThreadHeader.tsx#L214), [Button expansion](https://github.com/pingdotgg/t3code/blob/611132c171f3a821bd2e32f22261135cef6330ac/apps/web/src/components/ui/button.tsx#L11).

Tau already documents device-specific type roles in ADR 0029 and has `--touch-target`. Its desktop implementation mixes that scale with smaller fixed fonts and local sizes. `--control-font: 500 12.5px var(--sans)` in Settings bypasses Tau's Text size setting. Sidebar search deliberately subtracts 1 px from the 13 px control token. A consistent system should use shared role tokens and keep local exceptions only when their function warrants one. [Settings font](../../src/renderer/settings/controls.css#L7), [search font](../../kits/workspace/styles.css#L77), [type policy](../adr/0029-type-scale-per-device-class.md).

For Tau, the evidence supports 14 px text for ordinary editable fields, menu choices, and labeled controls; 16 px icons for common desktop controls; 32 px ordinary targets; and a separate 24 px helper role with 12 to 14 px icons. The user's enlarged sidebar footer can keep 36/18 as a navigation role. A broader 36/18 standard remains a valid preference, but should be assessed as an intentional increase over T3. Keep 12 px metadata, 13 px secondary copy, small chevrons, and touch targets separate from ordinary control sizing. This is a proposed Tau rule, not an implemented change or a T3 design requirement.
